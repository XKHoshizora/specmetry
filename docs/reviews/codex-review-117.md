`p5HolderFailures` 不只是新增一个打印字段。实际调用者包括：

- 本侧 `h.cleanup()` 返回后，`p5RealCheck` 以 `h.failures()` 填入 `p5RealFacts.Holder`，交给真正使用的 `p5RealJudge`。

### 3.2 不再被 holder 聚合类别豁免

`p5RealJudge` 对每个持有者失败分别添加问题，`p5Codes` 保留重复代码的数量。`p5RealVerdict` 不是把存在一个 `holder` 就算预期命中：

1. 问题代码及其数量必须与本侧固定预期相同。
2. W1 负向自检还要求 `Holder` 恰有一项、来源 `wait-observe`、`Planned=true`、`Count=1`，并可靠回收为 signal 9。
3. 其他真实 holder 错误产生额外项／代码；即使只有一个错误，来源、标记或次数不对也拒绝。
4. 链错误、接缝未命中／前提失败、协议 T、请求次数、回收不符及调用者核对失败分别进入问题列表，不能被 `holder` 预期覆盖。
