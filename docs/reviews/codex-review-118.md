## 4. G5 与 Q-4(a) 的技术裁定

### 4.1 规则和状态解码

§19.5 的 ABI 表、W1～W5、K1／K2、C1 与 §6.2、§10.1、data-model §4.11、MVP-EV-32 一致：

- 身份、结构、状态种类及相关核对成立之后，macOS 正常退出才按 Q-3(a) 取低 8 位。256／263／0x00ffffff 分别得到 0／7／255；不是新增全局 maximum=255。
- waitid 的 raw_status 第 8～23 位不进入生产事实或交换契约，是既有批准的信息保留决定；信号、读取失败、未知、身份不符和畸形状态不能掩码成正常退出。
- kqueue 返回的标志与所请求标志分开；W5 和 C1 依赖同一个未回收对象、唯一回收及规定观察顺序。保留原始观察、独立规范化 N、被测输出 M 与预测的层次，不以最终规范化相同跳过原始值预测。
- kqueue 的 EINTR、枚举 ENOMEM 的重试消耗原截止／预算；waitid 错误不被重试到成功而抹去。无法确认不当作空集合，错误出口有 F1／资源责任。
- 运行时字段核对只拒绝所列违规。§21.5:2719～2727 仍明确：稳定返回合法的错误值可以全部通过 W1～W5；没有恢复 Review 104 已撤回的保证。
- 保存可靠主进程退出码不证明用户指令已经执行、不证明整树结束，也不覆盖超时、取消、D6、D19／A12 或 qualifying。

固定公开 XNU 源码、用户态 SDK 布局与实际运行内核是不同证据。沿用 Review 100、104 已核对的 XNU 宏分支、p_xstat／p_xhighbits 路径及限定前提；本 PR 没有改写这些推演。布局探针不证明实际内核采用哪个宏分支，较旧版本所列源码也不自动证明所有 ABI 结构相同。

### 4.2 入口 E2 和 H1～H6

本轮重新读取官方 Go 标签及固定源码：`go1.27.3` 解析到 `2aae1000ea1d4b28923b96db28acf4e3b99d6aff`。`syscall6` 调用 runtime 再经 `errno(r1, err)`；后者仅在 `int32(r1)==-1` 时返回 errno，成功返回 0 时给出 errno=0。两个 runtime 架构桩先保留返回寄存器，再读取 `__error`。这支持过滤设计，不证明某次健康调用过滤前的 errno 实际非零。[固定 syscall 源码](https://github.com/golang/go/blob/2aae1000ea1d4b28923b96db28acf4e3b99d6aff/src/syscall/syscall_darwin.go#L326)、[arm64 桩](https://github.com/golang/go/blob/2aae1000ea1d4b28923b96db28acf4e3b99d6aff/src/runtime/sys_darwin_arm64.s#L527)、[amd64 桩](https://github.com/golang/go/blob/2aae1000ea1d4b28923b96db28acf4e3b99d6aff/src/runtime/sys_darwin_amd64.s#L553)。

| 假设 | 可采纳的证据及“成立”的准确范围 | 不能推出 |
|---|---|---|
| H1 构建／导入 | 固定 Go1.27.3、CGO_ENABLED=0 的两架构静态产物；跳板、唯一 _waitid 导入、每符号 bind／ordinal 指向 libSystem，检查方法的对照 | 实际执行二进制与静态产物逐字节相同、运行时镜像绑定已独立观察、未来 Go ABI 永不变 |
| H2 加载 | 两个已测组合实际启动到 TestP5，并执行 E2 原生场景 | 所有 macOS 13+ 组合都已经加载测试 |
| H3 调用 ABI | 固定入口的宽度／指针存活依据、39 次原生观察与 3 次 SDK 布局；已测组合中的调用按预测成立 | SDK 等于运行内核；任意合法值域内错误均能被发现 |
| H4 返回值／errno | 真实 ECHILD、EINVAL 返回及之后健康恢复；另有固定过滤源码 | 过滤前非零 errno 已动态建立／取样；H4 所有运行条件均动态验证 |
| H5 结构／语义 | P-5 原始值、重复读取及 C1 按预测；与 P-3 在同组 OS 构建上的预测和记录相符 | 同一次执行的 E1/E2 配对对照，或相同代码、Go／cgo 设置下唯一变量实验 |
| H6 EINTR | 真实调用结果先保存，之后接缝构造 (-1,EINTR) 检验消费者不重试及失败传播 | 原生 EINTR 穿过 libSystem／Go 跳板已验证 |

H1／H2／H3／H5 的“成立”应始终读作**已测工具链、架构、OS 构建与场景范围内成立**；§21.5 的表及 §148 已作这种限定。H4 是混合证据，H6 是消费者接缝证据，均不是整个假设的全称动态证明。

入口 E2 的 linkname／动态导入不是 `import "C"`，与纯 Go、CGO_ENABLED=0 的约定不冲突；它仍有固定工具链及未来收紧的成本。风险不仅在构建时，加载、ABI、errno 和稳定语义错误的范围仍然保留。采纳 E2 是在 Q-4(a) 既定路径下对技术候选的建议，不重新提出 E1、E5 或新的 ABI 风险接受。

### 4.3 是否还必须增加动态证据
