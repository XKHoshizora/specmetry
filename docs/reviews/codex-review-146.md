### 3.3 逻辑判定点

第 510～513 行与 §0.3 的精化保持了原资格规则：

- 锁串行化下，在发布者锁内读取时钟、检查锁存的逻辑点决定资格；不是“谁先拿锁谁及时”。
- 在该点恰好等于 D 或超过 D，均属晚到；锁存已经置位也属晚到。
- 结果与资格在同次临界区保存，资格只追加、不改写；后续当前成功不能追认及时。
- 不要求实际字段可见、解锁、调度与墙上时间硬实时原子。线程在逻辑点之后才被调度暂停，不另开一套物理可见时间判据。
- 父端读当前时钟用于置锁存及无终态分支的截止判断，不用于重算历史资格。

不存在因该精化而允许已知过期后新建诊断、继续写入、刷新或关闭的路径。已经开始的外部调用不被强制中断，原任务和外层登记表仍承担持有及晚到结果责任；这不代表已确认释放。

## 4. N-146-1：五状态表最后一行应区分结论不变与现在退出

**非阻塞精化；不保留 B-143-2-R/P。** 位置：主计划 §6.6 第 575 行，以及 §188 对第五行的转述。

该行把“暂定 1 或 2，不论诊断有没有终态、是否到期”映射成“(a) 或 (b)”“非零”。单独看它，遗漏了这一个可达组合：

1. 暂定为 1（例如对照不命中），父端 112 s 被状态变化唤醒；
2. D=120 s，锁存未置；诊断还没有终态，仍在按原截止收尾；
3. 第 5 步的 (a)、(b) 均不成立，应执行 (c)，继续等待；最终结论已经不会改善，但本次还没有退出。

因此，第五行的“(a) 或 (b)”不是对所有唤醒状态的完整枚举，“非零”只能解释为最终退出状态，不能是立即退出命令。

**为何不列为新 BLOCKER：** 第 567 行明确规定该表按第 5 步的唯一顺序解释；第 574 行已不限定暂定值地覆盖“无终态、未到期、锁存未置”，明确本次无出口；第 533～538、600 行也逐项写定同一顺序。第 575 行没有新增提前退出指令、取消诊断或转移责任的协议。结合其引用和第七项推演的“收尾照常”，可确定该行描述的是失败结论不可改善，不能覆盖 (c)。与上一稿不同，本稿不再有一个上位的总到期规则要求对此入口采取相反行为。

建议最小精化：将末行的分支栏写成“按 (a)/(b)/(c) 判断；(c) 时仍等待”，把结论栏写成“最终结论恒为暂定 1／2；实际退出只发生在 (a) 或 (b)”，退出栏标明“最终非零”。也可拆成两行。相应修订记录只追加，不回改 §188 历史。无需增加预算或改变责任。

固定实现审查须检查这个明确的既有语义：不得按暂定 1／2 直接短路第 5 步，也不得由表格自动生成只有 (a)/(b) 的实现。这是规格兑现检查，不是本报告新增的风险决定或授权条件。
