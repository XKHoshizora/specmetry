## 三、BLOCKER：B1-R 仍有未获批准的保证缺口

以下代码位置均指本轮固定 HEAD。按一个 B1-R 残余报告，四个窗口分别提供证据，不增加无关架构任务。

### A. mkdir/open：空替代目录会被当作刚建立的目录

位置：[newPrivateDir:313](../../internal/gitx/privdir.go#L313)，特别是 325～341 行。

`Mkdir` 与 `s.open(name)` 是两次操作。身份第一次从后者打开的对象取得；接着比较路径与该句柄、检查为空。这能拒绝持续的链接或非空替代物，却没有保存原 mkdir 所创建对象的身份。原对象与替代物都存在时，后续记录只能证明它接管了替代物，不能证明它最初创建了替代物。

**独立复验：Windows/amd64、NTFS；WSL Linux/amd64。** 使用原有 `testHookMkdir`，插点正好在 mkdir 成功之后、打开之前：

```text
rename(newPath, newPath + ".original")
mkdir(newPath)                         # 空的替代目录
继续原生产调用链
```

对公开 Clean 与 Log 分别执行，两平台均返回 `err=nil`／exit 0；替代目录已被写入并按正常流程删除，原创建目录仍留在 `.original`。Windows 此时尚无该私有目录的打开句柄，替换确实发生，不能援引后续 NTFS 的重命名拒绝。

已提交 `TestPrivateDirectoryReplacedAsItIsMade` 的插点正确，但只检查非空目录和链接；它没有证明空替代物也会拒绝。这里不是以另一个无关失败冒充拒绝。

**实际影响**：使用并删除了不能证明为本次创建的目录。没有据此宣称已覆盖其他账户可写入该空间，或已经造成客户数据损坏。其后建立的所有者记录不能追溯修复创建归属问题。

### B. Unix 最终核对/rmdir：会删除同名空替代目录

位置：[privid_unix.go:45](../../internal/gitx/privid_unix.go#L45)，调用者为 [removeOnce:459](../../internal/gitx/privdir.go#L459)。

`Fstatat(..., AT_SYMLINK_NOFOLLOW)` 核对身份后，另行执行 `Unlinkat(..., AT_REMOVEDIR)`。父目录句柄绑定了 tmp，但没有把最后那个子条目的身份作为删除条件传给内核。

**独立复验：WSL Linux 普通用户。** 仅在隔离副本的最终身份判断通过之后、`Unlinkat` 之前插入同步点，保持其余生产算法不变：移走刚刚核对的空私有目录，在相同名字放入另一个空目录，继续原 `Unlinkat`。Clean 和 Log 均返回 nil；替代空目录消失，原目录留在移走位置。

这个插点比仓库的 `testHookRemove("entry")` 更晚。后者位于 `removeEntry` 之前，替换后仍会遇到函数内部的 Fstatat，因而能被拒绝。该测试有效验证它实际覆盖的层次，不能推广为已关闭 Fstatat 与 rmdir 之间的窗口。

**实际影响**：误删替代目录条目。rmdir 不会在此调度中递归删除非空内容；不把这个结果扩大为任意目录树内容被删。但“仅为空目录”并不满足原先不删除替代对象的保证。

### C. Unix 所有者文件最终核对/unlink：会删除替代文件

同一 [removeEntry](../../internal/gitx/privid_unix.go#L45)，由 [removeOnce:450](../../internal/gitx/privdir.go#L450) 删除 `specmetry-owner`。

**独立复验：WSL Linux，Clean 和 Log。** 在最终 Fstatat 身份核对已通过后，将原所有者文件移到私有目录外的本测试保留位置，再在原名称写入 `keep replacement owner`，继续原 Unlinkat。两个入口均返回 nil；替代所有者文件被删除，原文件在移走处保留。

字节锁／flock 仍作用于原文件，不会自动锁住新文件。目录句柄正确绑定父目录，也不能把按名称删除变成按已验证 inode 删除。

**实际影响**：删除了另一个文件。此复验没有读取或修改真实用户文件；也没有声称攻击者能绕过保护进入 tmp。原保证明确包括锁／所有者文件，不能只保留目录内容而把这项排除。

### D. Git 路径往返：句柄保护没有覆盖 Git 消费的路径

位置：[Clean 的读取](../../internal/gitx/clean.go#L447)、[scanCall:35](../../internal/gitx/scan.go#L35)、[call.run](../../internal/gitx/call.go#L40)。

Specmetry 自己的索引副本读取已绑定句柄，但 Git 使用 `--git-dir=<路径>`，或使用 `GIT_GRAFT_FILE`／`GIT_SHALLOW_FILE` 的路径。前后复核不能辨认中间发生并恢复的变化。

**独立复验：WSL Linux，真实 Git 2.43.0。** 在隔离副本给 `commandIO` 前后增加同步点，分别位于调用方复核之后和 Git 返回之后、下一次路径复核之前；没有伪造 Git 输出，没有运行远端或外部 Helper。

- **Clean**：正常的干净两提交夹具；把原私有目录移开，复制它到原路径但移除替代副本的 index，运行真实 Git status，然后恢复原目录。Clean 返回 dirty／nil。它使用了替代目录；这例没有证明 false-clean，不能写成错误 ready 已复现。
- **Log**：正常两提交夹具；把防护私有目录移开，在替代目录的 `none` 写入 tip SHA，成为有效的浅边界／无父 graft；真实 Git 完成后恢复原目录。Log 返回 nil，但 callback **只收到 1 个提交，预期完整历史有 2 个**。后续复核看到原身份，未发现往返。

**实际影响**：扫描防护“该文件不存在”的前提可以在本调度中失效，严格读取可能漏读却成功。本轮没有把该结果延伸成已经独立复现数据库游标发布或持久化损坏；问题发生在当前公开 Log 入口，属于 B1 私有空间调用链，不是重新审查未变扫描算法。

### B1-R 的最小处理要求

当前这些剩余窗口不能仅通过多加一次普通路径检查宣称消除。最终核对与按名删除、创建与取得句柄、外部 Git 进程按路径访问，各自具有不同的原子性条件。

在继续合并前，需要二选一落实，而不是把披露自动变成批准：

1. **保持现有保证**：实施方针对上述对象绑定提出并验证能够兑现保证的机制；无法可靠绑定时保守失败或保留未知对象。特别是不能以 rmdir 只删除空目录、所有者文件位于私有目录内，代替不误删的证明。任何改变正常清理／遗留生命周期的方案也须明确其影响。
2. **若选择保留窗口**：先由负责人明确裁定精确的局部保证调整，范围至少包含同用户往返导致 Git 错误读取、Unix 替代文件／空目录删除、以及所有平台的空目录接管。同步规范、验收与错误／清理语义，随后再复审。不能将跨用户保护已成立解释为以上取舍已获批，也不能泛化为其他存储、版本或隐私保证可放宽。

本报告没有为这些窗口接受风险，也不要求提前实现后续工作包或全面重构存储层。

## 五、句柄、身份与清理链中已成立的部分

| 操作 | 实际绑定方式 | 已成立的保护及边界 |
|---|---|---|
| Scratch 准备 | Ensure 后记录解析路径的完整根链，打开 tmp 的 Root／File，比较句柄身份 | 持续的根替换和指向原处的链接会被发现；不打开数据库 |
| 私有目录创建／打开 | tmp Root.Mkdir 后再 OpenRoot，记录打开对象的身份 | 防路径逃逸、拒绝非空／链接替代；不证明 mkdir/open 空替代物属于最初创建 |
| 配置、HEAD、索引等写入 | privateDir 的 os.Root | 原目录移动后仍访问句柄绑定的目录，不跟随外部路径去写替代根 |
| 索引副本及 shared index 读取 | `indexIsSparse(p.dir.root.ReadFile, "index")` | 两者由同一 Root 读取，保留 B2 的解析边界；原公共 IndexIsSparse 的行为未发现直接回归 |
| Git 使用 | 私有路径或防护文件路径，使用前／删除前复核 | 持续变化拒绝；不能排除中间往返 |
| 内容删除 | privateDir 的 Root.RemoveAll | 不因外部根路径替换递归删除另一个根中的内容；这里不把 Root 当作 Git 的句柄传递 |
| Unix 所有者文件和目录条目删除 | 父目录 fd 下 Fstatat，再 Unlinkat | 父对象固定；最后名称到对象的映射仍有第三节 B／C 的窗口 |
| Windows 所有者文件／目录条目删除 | no-follow 打开，读文件 ID，在同一 handle 上设置 FileDispositionInfo | 核对后删除作用于所打开对象，和 Unix 的两个系统调用不同；没有从 NTFS 运行结果推导所有文件系统均已验证 |

Go 的 [Root 文档](https://pkg.go.dev/os#Root) 说明 Root 在支持的平台上持有目录引用，目录移动后仍访问原对象；这不是最终子条目身份的条件删除接口，也不自动绑定外部 Git 的路径。已同时核对本机 Go 1.27.1 的实现。

Windows 身份由 handle 取得卷序列号和文件 ID，优先使用 FILE_ID_INFO，回退到已有文件索引；没有继续使用会延迟按路径查询的 SameFile。no-follow 打开拒绝 reparse point，删除在核对身份的同一句柄上设置。Microsoft 的 [CreateFileW 共享规则](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) 支持区分共享删除与重命名；具体的父目录重命名行为仍按本机／CI 的观察记录，不推广到 ReFS 或 Windows 双账户。

遗留清理先要求精确名字、真实目录、可取得所有者文件锁，以及记录中的目录和文件身份一致，再走同一删除流程。复制记录不能匹配副本的新身份。活跃条目、无记录、记录不符、链接和旧布局同级 `.lock` 均保留；真正模拟崩溃的遗留正常移除。该记录是受保护命名空间下的生命周期依据，不是对同 UID 进程的身份认证。

失败复核后关闭的都是本次实际持有的句柄／锁，不再按变化后的 tmp 路径删除同名旧锁。每次删除重试重新核对根链与目录，正常同一对象的临时失败仍能重试成功。

Scratch.Close 的正常重复关闭、关闭后使用、零值、正常复用均受控；既有取消与失败路径回归通过。调用点增加了 Close，调用约定为读取结束后再关闭，没有把并发 Close／正在读取定义为已支持的使用方式。没有发现本轮需重新开启 B2、B3、N1 的直接回归。

NewScratch 会创建和清理私有区，不是纯只读探测；它不打开数据库不代表未来命令可在版本拒绝前任意调用。普通 Open／doctor 和拒绝契约本轮未改变，未来接线仍须保持原有先后约束，本轮不提前实现 CLI。

## 六、测试覆盖与文档表述

现有 12 项 private-directory 测试均有有效用途，不能因未覆盖更晚窗口而否定全部证据：

- TestRemovalAttemptsCheckTheDirectory 的 hook 在某次删除尝试中替换并返回临时失败，下一次尝试必须先复核，覆盖原来的重试漏检。
- TestScratchRootReplacedWhileInUse 实际放入复制的所有者记录、见证文件和旧同级锁；Linux 的拒绝与后续清理保留断言成立。
- TestScratchRootRedirected 在 Linux 中实际改变 tmp／数据目录；根链检查发生在新写入／Git 使用前。
- TestRemovalRetriesTheSameDirectory、生命周期和遗留清理给出正常重试、正常释放、活跃条目保留、取消、所有者文件保留后可清理、所有者文件已去除则保留空目录等对照。

**NON-BLOCKER N1：最终核对窗口的描述需要更精确。** [TestRemovalChecksWhatItRemoves](../../internal/gitx/scratch_test.go#L319) 的 `testHookRemove("entry")` 位于 removeEntry 的最终身份核对之前；它并未在 Unix 的 Fstatat 与 Unlinkat 之间调度。[review-resolution §69](../review-resolution.md) 中的“核对之后、删除之前”“空的替代目录不被 rmdir”等说明，应写明是外层复核之后、内层最终核对之前。不得把该用例当作最终窗口已安全的证据。这个 N1 是本轮证据表述问题，不是重新打开 Review 058／059 的并发快照 N1。

本轮插入的 Unix 同步点在**最终身份判断通过后、原 Unlinkat 之前**；mkdir 调度直接使用原有的正确插点；Git 往返同步点包围实际 commandIO，而不是提前触发根链错误。它们不改变生产算法和返回结果，只控制本测试对象的调度。所有原始行、编译产物和日志留在仓库外副本。
