## 3. B-130-1：D 的终判与诊断出口

### 3.1 原反例已被正文排除

位置：`docs/wp2.5-implementation-plan.md:1710`～`1724`。

第 13 条已撤回“到 D 后打印每条未决项再退出”的顺序。现在将诊断与终判分开：

- `m.Run` 返回后，若仍在 D 前，取得字段快照并先登记唯一诊断任务；诊断在锁外写输出，结果在锁下发布。
- 父端只等待原 D，不为诊断重新取预算。到截止消费已发布状态后直接 `os.Exit`；此后不打印、刷新、关闭、查询或等待。
- `m.Run` 返回时已到 D，不登记诊断，直接走截止出口，保留诊断缺失。
- 已启动诊断的写入错误、未完成及缺证都使包失败。完整诊断不再是选择非零退出的前置。

因此，原事件序列“工具／请求／关闭未返回 → D 到达 → 父端同步打印 → 输出背压阻止退出”不再是允许的父端路径。输出任务可以仍未返回，但父端不会等待其外部调用，也不通过对输出端再 Close 来换取退出。

快照、任务登记与状态发布沿用原短状态锁；真实写入在锁外。没有新增由输出任务持锁跨 I/O、父端取得该锁才能退出的依赖。这里认可普通短临界区下的截止出口，不承诺硬实时调度，也不要求单个写入调用能被强制取消。

第 1724 行明确只约束 c9lint 自己新增的终判／诊断链。`m.Run` 返回之前的 Go 测试框架输出不由本次修订改造；不能把本条扩大成整个测试框架在绝对墙钟 D 必定终止的承诺。这与本轮限定范围一致。

### 3.2 四类路径与唯一退出状态

需要合并阅读第 1716 行的一般退出规则与第 1719～1720 行的诊断失败规则。不能只取“工具记录健康则否则为 0”，丢掉后文明确要求非零的诊断缺失／错误分支。

用逻辑条件概括当前条文：**只有 `m.Run` 成功、必需记录按既定期限满足成功条件且累计无失败、诊断在 D 前成功完成时，才允许退出 0。** 任一条件不满足为非零；已有失败持续保存。

| 路径 | 当前正文推出的唯一结果 |
|---|---|
| 及时完成：`m.Run=0`，必需记录健康，诊断在 D 前成功完成 | 退出 0；可提前结束，不必强制等待满 D |
| 已有失败：`m.Run` 非零，或工具／启动／关闭／请求／注入／放弃等已有失败；诊断正常 | 非零；诊断成功不恢复工具或测试成功 |
| 到 D 仍有未决任务／未知释放 | 非零；未决责任继续由原记录持有，不再为打印或收尾等待 |
| 工具记录原本健康，但诊断写入出错或到 D 未完成 | 非零，并保留诊断缺失／未完成；不能因工具健康而成功 |
| `m.Run` 返回时已到 D，诊断未启动 | 不启动新诊断；它没有在 D 前完成，按缺失／未完成规则非零；不借“尚未登记”绕过诊断要求 |
| D 后诊断成功或旧工具完成 | 只保存晚到状态；既定失败和缺证不恢复 |

第 1719 行的“诊断缺失”与第 1720 行的非零规则共同覆盖未启动情形；没有据此给“全表健康但诊断缺失”开一个退出 0 的例外。实现不能把“未登记”误当作“诊断已成功”。

诊断是一个时点的副本，后续到达的结果不在该输出中，正文已如实说明。父端最终消费的是登记表持续保存的状态与诊断任务结果，不是将一份较早的诊断快照当成最终有效性证据。若仍有可能产生必要结果的未决任务，到 D 就已经失败，不能通过快照中未出现错误来通过。

### 3.3 判定函数、TestMain 与回归的接线

第 1723 行把等待／诊断／终判放在一个可直接测试并返回退出状态的函数中，TestMain 只以该返回值调用 `os.Exit`。本轮在**设计层面**的接线成立：被测判定可以返回，夹具不需要让整个测试进程退出；实际 TestMain 不能再在该返回值之后同步补写诊断。

落实代码时必须把 `m.Run` 的返回值保留为该函数可见的判定输入，不能让它只看工具表。第 1716 行已经写定这一要求；第 1723 行列出的 D、登记表、输出端不是一份禁止补充状态输入的固定 Go 函数签名。可用明确参数或已保存的判定状态传递，不需要新增产品选择。本轮没有代码，因此不冒称实际 TestMain 接线或错误消费已动态验证。

第 **1535** 行的固定回归与第 13 条使用同一判定函数，能够覆盖上轮原反例：

1. 用例预先构造已有失败与受控输出，诊断写入不返回。
2. 被测函数到它的截止仍返回非零，并保存诊断缺失／未完成。
3. **先保存被测判定，再释放写入器**；`t.Cleanup` 经 `sync.Once` 兜底，避免重复释放。
4. 在夹具的预定截止内确认诊断任务返回；未返回则夹具自己失败、保留未知，并继续持有任务和写入器。

第 **1525** 行原有规则说明这些夹具用自己的登记表与较短截止，不占用包的终判。因此可在包 D 内预先给判定截止和夹具收尾留出顺序：`d_case < d_fixture ≤ D_package`。先在较短的 `d_case` 保存拒绝，再释放并在已有 `d_fixture` 内核验返回；没有要求在同一个已经到期的时点之后完成释放，也没有滚动重取包预算。

实施时须确认假写入器确实进入阻塞点，再观察未完成／非零结果；若未实际写入或未命中，只凭已有失败得到非零不能算本回归命中。这个要求是“诊断输出任务一直不返回”这一固定构造的实现核验，不是本轮已经取得的接缝证据。未来测试应直接断言缺证状态与返回值，不能只检查错误文字。

## 4. N-130-1／2 与关闭项的直接回归

### 4.1 N-130-1

生产计划 **1682** 与链接计划 **269** 的规则 6 已同步：

- Closing 封闭新的预留；无有效预留的旧快照不能授予使用权限。
- 合法 Reserved／Running 在归还之前保有使用责任，按规则 5 使用所预留的 fd。
- 唯一关闭者仍须等使用责任归还后才能真实 Close；真实 Close 后任何旧使用责任都不能继续使用该 fd。

这消除了原概括语句可能把合法 Closing 期间的使用也禁止掉的歧义。没有改为先 Close 再请求、额外预留或无锁旧快照动作。**N-130-1 关闭。**

### 4.2 N-130-2

生产计划 **1698** 与链接计划 **285** 的第六种交错已明确：

- 到期放弃先发布、归还责任，不发终止请求。
- 只有 Wait 已发布并封闭时，唯一关闭者才随后 Close 一次。
- Wait 还未返回时，放弃本身不触发 Close；fd 保持 Open，由原责任记录持有，等待原 Wait 的发布／封闭。
- 请求已不是 None，不能因为 fd 仍 Open 再预留第二个请求。

与规则 2／4 的关闭前提一致，没有把放弃当作回收或释放证明。**N-130-2 关闭。**
