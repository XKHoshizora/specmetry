## 2. 四项文档阻塞

### B-143-1：有限实现的对照预期与外层终判没有闭合

**位置：**[限定取证计划](../wp2.5-c9-limited-evidence-plan.md) §4.3，第 247～255 行；§5.1／§5.2，第 271～293 行，尤其 LC-5 第 288 行；§7.1，第 324～331 行。直接依赖：方法规格第 804～805、809、833～835 行；实施计划 §12.14 第 11～13 条，第 1713～1727 行。

#### 具体范围矛盾

计划明确不实现 B′、规范表示、批准登记和 C；LC-5 却要求 V-19b、V-20 两分支、V-24、V-40、V-42 的“失败集合与未评估的集合……完全相同”，且逐项比较。方法规格中的这些行并非全都只有 A/B：

- V-24 明确要求 `J-1（A1-a）` **及 `J-6（LP-3）`**，并继续 B′1～B′4、LP-1／2／5／8；LP-4／6／7、B′6、C 则未评估。
- V-19b、V-20、V-40 都保留 B′ 中可计算的部分。

**反例路径：**假的调用者给出 V-24 的 go1.27.4 输入；有限工具按 A1-a 正确拒绝且不启动后续调用；由于 B′ 不实现，无法得到按旧清单比较的 LP-3／J-6。若只返回 J-1，LC-5 不符合“完全相同”；若为通过 LC-5 补实现 B′，则越出 §4.3 的固定范围；若把“不在本工具中实现”直接改记成旧方法的“未评估”，也不等于该 V 的完整固定预期。

这是确定的静态冲突，不是缺少运行证据，也不是要求本轮扩大到完整清单判定。

#### 计划故障与作业结论的域

LC-3 正确命中的关闭注入会产生 J-1；LC-8、LC-9 也故意制造预算或控制失败。§5 要求这些预期失败算有效命中，但 §7.1 又把“其他 J-1～J-3”列为作业“未完成”；引用的旧工具协议还规定登记表中的注入错误、失败及晚到错误不能被测试通过覆盖。

当前没有明确本工具哪些登记属于被测负向夹具、哪些属于实际采集与外层收尾，以及如何把一个失败的内层判定消费成“有效负向对照”而不删除它。于是可以出现两种不相容的实现：所有健康命中的负向对照仍使作业“未完成”；或者为了通过而过滤 J-1／关闭错误，连额外真实故障也被豁免。§5 的“进入记录＋结果相同”不足以单独解决这层接线。

**最小修订：**

1. 在本计划内写出 LC-5 的 **A/B 投影表**：每分支的输入、必需成立／失败／未评估集合，以及明确排除的 B′／C。不修改原方法的完整 V，也不实现 B′；“本工具不覆盖”与“已有依赖未成立导致未评估”分开。
2. 分开真实采集域、被测夹具域和外层对照有效性／清理域。被测预期错误继续保留；外层只能按明确的站点、类型、来源、次数及完整预期集合接受该负向结果。额外真实错误、未命中、外层关闭错误、未知清理或晚到真实错误必须使对照无效／工作未完成，不能按聚合类别豁免。
3. 说明 §7 的 A/B 条件指真实采集域；预期内层失败不直接混入真实采集的 J 集合，而其记录和外层有效性仍全部进入终判。写定与 TestMain、旧登记表的边界及四种总结论、退出状态的映射。

这些是本有限工具的范围与消费规则，不重开旧收尾协议的正确性。

### B-143-2：新增落盘与 manifest 没有接上父端截止和资源责任

**位置：**限定取证计划 §6.3，第 317～319 行；§4.2 第 233 行；§9.3 第 392～395 行。直接依据：实施计划 §12.14 第 13 条，第 1723～1730 行，以及同步分析工作第 1735～1737 行。

计划要求记录在 D 之前“逐条写出并落盘”，再写 manifest、在日志打印 manifest 与每个文件的哈希。原协议明确的是工具子进程管道、pidfd 及一个诊断任务；没有定义这些新增持久文件的打开、Write、Sync（如果“落盘”包含它）、Close、哈希和发布责任。

**允许的失败顺序：**父端在 D−ε 开始一次记录 Write／刷新／Close，外部操作未返回；D 到达后父端没有机会执行只消费状态的出口。或者采集已被放弃，但工作 goroutine 持有尚未关闭的记录文件，这与原协议“只持有输入和结果、不持有外部资源”的前提不同。另一路径是正文记录成功而 manifest／哈希打印未完成，原工具登记均健康，却没有明确哪一项失败进入终判。

“在 D 前开始”“workflow 最多 20 分钟”“artifact always”都不保证操作在 D 前返回；作业结束、进程退出及 runner 清理也不证明文件或任务已可靠收尾。本报告不要求单次系统调用硬实时返回，而是要求父端不因新接入的同步外部操作丢失既有截止出口。

**最小修订：**在本计划写清新记录链如何使用已审模式：先登记、任务在锁外执行、父端只查询已发布状态，所有等待用原 W／D、不重取预算；半构造文件及每个输出端有唯一关闭者，真实 Write／Sync／Close 错误持续消费；未完成任务、输入与句柄有持续持有者。明确“落盘”的实际要求、完整文件和 manifest 的发布条件、晚到结果不恢复结论。哈希打印应纳入已有唯一诊断任务或写定同等截止接点，不能在 D 出口之后追加同步打印。缺失／部分／关闭失败的证据不能被 artifact 上传成功升格为完整。

格式的具体编码可以留到固定实现审查；**谁执行、谁关闭、谁消费失败、D 时谁还能返回**须在授权实现前写定。这不是要求全面重做 pidfd 或既有关闭协议。

### B-143-3：commit、tree 与 GITHUB_SHA 不能字面相等

**位置：**限定取证计划 §6.3，第 314 行。

该条先指定“完整提交 SHA”，再说 workflow 打印检出的“提交与树”，工具记录 GITHUB_SHA，接着要求“三者必须相同”。它没有区分提交身份与树身份。按字面把 tree 也放入相等比较，会把健康检出必然拒绝；若“三者”意指只比较三处提交值，则树的比较对象及其关联没有写出，不能由实施者自行选择另一种规则。

受审对象已有具体例子：提交 `61e6991…` 的树是 `f7d9e94…`，两者不同且应不同；同树的 PR 合并快照 `adba69f…` 又是第三个提交身份。

**最小修订：**对拟议的 push 运行明确两条关系：

- `固定受审提交 C = 实际 checkout 提交 = 本次 push 的 GITHUB_SHA`；
- `tree(C) = 实际 checkout 的 tree = 预先记录的受审 tree T`。

按该关联继续绑定工具源码、workflow、运行记录和派生记录，不要求 `C = T`；当前 pull_request 常规 CI 使用合并快照另记，不能代入未来 push 取证的固定提交。文档即可修正，无需运行任何命令验证候选实现。

### 3.3 T-4 未定与 12／24 比较

静态候选表包含运行时信号实参，不能在 T-4 未定时把 24 项全称作已经确定的违规或批准条目。当前计划的取证字段可以支持一个相容解释：

- “发现”在此次候选比较中是**冻结对象集合中的源码对象引用**；12 是不同源码位置口径，24 是六配置条目口径，不把调用链重复计数。
- 信号实参是否常量 SIGCHLD、其他常量或运行时值另列诊断；冻结字面下能确定的结论与依赖 E-1 的最终分类分开。
- X1／X4 对象引用不进入冻结候选比较集合；不得因为诊断发现了这些引用就自动扩充例外或改变对象表。

按这一限定，T-4 可以留到 N3，不必为了“未定”停止原始对象引用采集。建议在 LQ-4／§4.4 直接定义“对象引用发现，不等于最终违规”，消除读者把第一类规则的违规集合与候选引用全集混用的可能。报告记录不能借此称原始路径已覆盖或风险已接受。

`24de6a735c1605e39b6381e6962787faa5c59adab896fb66dbc1ac8b6afcb297`

### 4.2 N-143-1：消费者一致性核对不等于标签使用认证

**位置：**限定取证计划第 240 行；与第 162、238 行对照。

### 5.2 四种总结论

- 对照未命中、预期不符、固定身份错误或解释工具有缺陷：无效。
- 真实采集预算／调用／读取／关闭／输出失败或未知：按已写定的未完成规则保留，不能被负向对照的预期豁免。

- 预先明确的平台不适用与未命中不同；无法构造、未获准真实调用而没有覆盖、测试失败不能临时改写成平台不适用。

已有结果不可被晚到的真实错误反向伪装成“从未评估”；晚到真实错误却须使先前的有效性结论降级。每条错误的来源和持续状态都应保存，不仅保存最后的主分类。
