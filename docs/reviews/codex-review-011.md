### B1：`$(` 前缀错误豁免明文密码——已关闭

修复与批准契约一致：

- [rules.go:63](../../internal/secrets/rules.go#L63) 仅识别四种完整引用：`$NAME`、`${NAME}`、`%NAME%`、`$env:NAME`。`$()` 已失去整体豁免。
- `${NAME}` 后拼接明文密码会继续接受检测；字段中的其他候选也不会被环境引用或占位符掩盖。
- [regression_test.go:15](../../internal/secrets/regression_test.go#L15) 确实经过 `New → JSON → Reject`，检查拒绝结果、字段位置、规则编号和错误脱敏，并非只测试内部辅助函数。

在仓库外临时副本中验证了三个原始反例，合成密码的普通输入均作为阳性对照。探针中的密码由 `"s3cr3t" + "Pass9"` 在运行时拼接：

| 反例 | 修复前 | 修复后 |
|---|---|---|
| `password=$(true)<合成密码>` | 错误放行 | 拒绝 |
| URL 密码为 `$(true)<合成密码>` | 错误放行 | 拒绝 |
| `password=$(<合成密码>` | 错误放行 | 拒绝 |

将本次新增的回归测试放入父提交的临时副本后，三个反例均在“应拒绝”的断言上失败；相同测试在目标提交上通过。另行运行的独立公开接口探针也确认三个反例均被拒绝，并使用退出码 **2**。阳性对照成立，测试实际执行了被审查逻辑。

四种合法引用仍可通过；错误字符串和 JSON 错误响应未回显匹配文本。既有的同字段混合引用与真实密钥、前一个候选可豁免而后一个必须拒绝等场景也继续通过。未发现本轮引入的明显新误报或豁免绕过。

### N1：无条件规则产生不必要的匹配分配——已合理解决

[rules.go:83](../../internal/secrets/rules.go#L83) 对无附加判断的规则使用 `MatchString`；URL、Bearer、通用赋值等有附加判断的规则仍逐个检查候选。规则顺序、首个命中规则的报告方式和错误格式保持不变。

[regression_test.go:89](../../internal/secrets/regression_test.go#L89) 先验证实际命中，再测分配次数。旧实现独立运行得到每次 **4017 次分配**并失败，修复后通过。

测试采用宽松上限（每次不超过 50 次分配），不依赖执行耗时或精确零分配；`testing.AllocsPerRun` 包含预热。结合目标提交三平台 CI 的成功结果，未发现不合理的平台敏感性，也没有要求为这个测试引入额外重构。
