## 4．剩余H4覆盖：可以作为明确范围的证据路径

### 4.1 静态依据实际证明什么

本轮重新读取固定Go1.27.1提交 **`862c888e612ac346c7c4d99c9392bdfd265f33b0`** 的两个架构调用桩、syscall6及LockOSThread说明。

- [syscall_darwin.go:330](https://github.com/golang/go/blob/862c888e612ac346c7c4d99c9392bdfd265f33b0/src/syscall/syscall_darwin.go#L330) 的 `errno(r,e)`：当 `int32(r)==-1` 时返回e，其他情况返回0。
- [syscall6:406](https://github.com/golang/go/blob/862c888e612ac346c7c4d99c9392bdfd265f33b0/src/syscall/syscall_darwin.go#L406) 确实先调用syscalln，再通过上述过滤返回err。
- [arm64:560](https://github.com/golang/go/blob/862c888e612ac346c7c4d99c9392bdfd265f33b0/src/runtime/sys_darwin_arm64.s#L560) 和 [amd64:563](https://github.com/golang/go/blob/862c888e612ac346c7c4d99c9392bdfd265f33b0/src/runtime/sys_darwin_amd64.s#L563) 都在真实目标调用之后读取线程errno；过滤前读数与公开返回值分层成立。
- [proc.go:5658](https://github.com/golang/go/blob/862c888e612ac346c7c4d99c9392bdfd265f33b0/src/runtime/proc.go#L5658) 只证明线程绑定，没有errno保留保证。

因此，**对这份实际过滤逻辑，成功返回值为0时，无论输入e是0还是任意非零值，输出err都为0**。这是对固定函数的直接推演，不依赖“本轮某次TLS里究竟残留多少”才能成立。它也不证明E2尚未构建的包一定调用了这份逻辑，所以仍要用入口覆盖、构建/链接证据及实际调用检验来关联。

| 层次 | 可以支持 | 不能据此声称 |
|---|---|---|
| 固定源码 | 指定过滤函数对成功/失败返回值的规则；两架构桩的errno读取设计 | 未来工具链不变、候选包已经正确绑定、全部运行环境已验证 |
| 计划中的真实ECHILD/EINVAL | 在所测组合上，真实错误经过实际入口得到预期返回值与错误码 | 所有errno都曾原生触发，或真实EINTR已穿过跳板 |
| 错误后健康调用 | 对同一实际入口，公开返回0/err0，正常R/N/M与预测相符，错误后恢复正常 | 健康调用当时过滤前e确为非零、已动态施加并观察残留负载 |
| 未观察的过滤前e | 当前只能如实记为动态覆盖限制 | 自动confirmed，或自动成为负责人已接受的L |

### 4.2 本轮明确的技术评价及条件

**可以**用“固定工具链源码依据＋计划中的真实错误/健康恢复”准备受控P-5并供负责人选择Q-4(a)。本轮**不认为必须再增加过滤前动态取样**才能准备该计划。

理由是：原B-P5-1的反例只能推翻“我们已经动态检验非零残留”的论断，不能推翻固定函数对任意e的条件分支。第三稿已撤回前一种论断；在没有新的具体反例时，不把对固定函数的证明又升级为必须排除任意编译器、运行时或部署库行为的实验。

这一技术评价具有以下必要前提，不是无条件认可：

1. 计划定稿时选定**精确工具链补丁版本及固定来源**，重新核对相应版本的syscall6/过滤逻辑/两架构桩，不能只引用1.27.1而实际自动升级到别的版本。
2. E2真正绑定该syscall6，参数、符号、跳板、返回值的32位解释符合声明；不能改成未过滤入口或自制过滤器，却继续引用这里的证明。入口覆盖与绑定须在实际原型中查验。
3. CGO_ENABLED=0、原生两架构、同一固定代码点、真实错误/健康对照、布局前提、独立预测及清理都取得有效结果；失败/未执行/未知不算通过。
4. 报告继续分开“静态设计被支持”“计划中哪些动态检查实际通过”“哪些未动态覆盖”。不用一句“H4整体通过”掩盖证据层次。
5. 负责人作Q-4决定时明确看到这一覆盖组合与缺口；以后实际证据的独立审查仍可因实现绕过过滤、错误传递异常或其他具体反例要求修订。当前不将缺口自动登记为已接受L，更不豁免错误结果。

这足以支持**选择受限证据路径**，不等于E2已验证、P-5获授权或规范可冻结。如果负责人要求把“动态观察非零残留”本身也作为验证目标，需要先另定最小观察方案；本报告不为其增加授权或强制要求。

### 4.3 N-106-1：没有方案，不等于技术上不可能观察

**位置**：规范`:2877`～`:2879`及§130的对应理由。公开syscall6不返回过滤前e，是有依据的；但从该API不可取得，不能推出“要观察同一实际链路，只能改运行时或换入口”的穷尽性结论。

本审查**不确认后一个必然性判断**。例如，外部调试观测与API返回值是不同能力；[LLDB官方教程](https://lldb.llvm.org/use/tutorial.html#setting-breakpoints) 就描述了在已加载程序中设置断点及观察执行状态。这不证明一个安全、可复现的P-5取样方案已经存在或适合当前权限/预算，也不授权引入调试器实验；只说明不能用“API不暴露”排除所有观察手段。

**最小建议**：改为“本计划不包含在同一实际E2链路上取得过滤前读数的方案；复制包装或改入口不能冒充该链路证据。若以后确需此目标，先另审方案及其影响。”§130是既有处理记录，后续追加澄清，不回改历史。

本项为**NON-BLOCKER**：不准确之处是未被证明的穷尽性理由，当前受限计划已经准确声明不取样；本轮采纳证据路径的依据是§4.1的过滤设计与实际入口关联条件，**不依赖“动态取样不可能”**。无需为了消除这个绝对措辞，本轮先发明或实现观察机制。

## 5．分类、对照、预算与所有权

### 5.1 终判推演

| 合法事件序列 | 应得的唯一结果 |
|---|---|
| 第一次真实调用成功；注入一次EINTR；消费者按规则拒绝；无额外错误且清理核实 | 内层invalid/非零，门禁通过；不算原生机制confirmed |
| 同一对照不注入 | 读2次，W5核对；成功才为confirmed。第二次是重复观察，不是错误后重试 |
| 注入前真实调用已出现计划外错误，之后仍改写成EINTR | 真实错误持续记T；不能只保留预期一条理由让门禁通过 |
| 正常原生值、错误返回或健康恢复与预测不符，工具前提有效 | refuted；不是一律吞成“工具无效” |
| 上一行叠加工具报告/解析/关闭/身份错误，或清理/最终状态未知 | T优先，invalid；不得靠预期拒绝或成功补救豁免 |
| 可靠环境不具备 | unsupported，不计confirmed；元数据读取未知不是已确认环境不具备 |
| 布局invalid/refuted、预算不足、未执行或未命中 | 目标不能confirmed；保留布局自己的理由，按已有T/E规则处理 |
| 健康原生全部匹配 | 才可confirmed；原始R预测仍检查，不能因低8位相同而跳过差异 |

EINTR不重试仍与现行§19.5的waitid错误出口相容；没有给kevent新增政策。包装返回**之后**的EINTR接缝只支持消费者分支，不证明真实EINTR穿过libSystem/跳板，第三稿已经明确这一限制。

§21.9写定了结果先保存、T持续保存、外层工具错误不可豁免、先记录被测状态再补救、未知归属零动作。因此本轮没有发现一条**文档允许的**假通过或丢失失败路径；实现尚不存在，不能把这些规格写成已经运行验证的保护。

### 5.2 截止的范围与算术

设P-5顶层开始为S，套件截止为T：

`D = min(S + 180s, T − 30s)`

一次运行从s开始时：

`d = min(s + 60s, D)`，且准入要求 `D − s >= 60s`。

它不允许每个子步骤、重试或内层重新得到180秒。30秒留在D之外，60秒包含在D内。时间不足必须记为未执行/不完整，不能降低次数后仍宣称计划全通过；到期后清理失败或结束未知继续invalid。单次系统调用不具备硬实时保证，与这些用户态期限分开。

| 组别 | 本审查采纳的期限口径 |
|---|---|
| P5.layout、静态检查、39次原生检查及两个新门禁/对照 | 同一个D；每次按单次派生截止。内层接收外层绝对截止，不自建新3分钟 |
| `control.p5-w-exit7` | 也是表中P-5运行，适用“每一次运行”的d与D；不能因ID以control开头而逃出预算 |
| 经E2重跑的7个P-3故障门禁与2个旧对照 | 规范明确**不纳入D**；在TestGate沿用已有门禁及P-3场景期限，并受同一套件15分钟总截止限制。不计入“P-5顶层3分钟”的耗时保证 |
| go test编译/链接 | 不是测试二进制的`t.Deadline()`执行区间；受作业20分钟及既有构建失败传播约束，不能冒称D已约束编译 |
| D后的最后收尾 | 使用保留的30秒且不得越过套件截止；不能到期后又逐对象重新取得无总上界的完整清理预算 |

新表原生次数为21＋9＋3＋6＝**39**，布局3次、静态每作业1次、新故障门禁1次及健康对照1次；旧门禁7项及旧健康对照2项各1次另列。不把不同层级合并成原生confirmed，不把计划次数写成已执行数量。

算术相容不证明实跑能在D内完成全部负载。若实际不足，应按既定失败规则报告，不擅自增预算或重跑。本轮不作耗时实验。
