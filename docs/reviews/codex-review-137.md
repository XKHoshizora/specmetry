### 3.3 同一个解码器、重复 idx 与精确失败定位

`:365` 明确生产 M.unknown 和 HC-6(iv) 均走“表示字节 → 同一个严格解码器 → 同一个 M.unknown”。M.unknown 只消费解码后的名字，其余字段用于追溯，不能为变体另造简化的名字检查。

HC-6(iv)（`:432`）不修改真实 L 或 A，而是复制 R(L)，在末尾追加一条完整 LF 行：复制第一行，只把 name 改为 `modernc.org/libc.Xexecve.weird7` 的十六进制，其余六字段保持。独立差异核对要求原 R(L) 是完整字节前缀，余下恰好为该行；记录追加偏移、长度、空的原值、新行和新行号。L 没有行则未构造／无效，不能算命中。

重复 idx 是**明示的合成输入**：`:392` 规定解码器不检查顺序或 idx 唯一性，M.unknown 不读 idx，因此不会先被一个隐含的唯一性约束拒绝。它仍须是严格七字段、合法数值及十六进制的输入。生产 L 的顺序与真实索引要求没有撤销；对照能解码，不证明其为真实 ELF 的输出。

预期失败必须定位到**追加的解码行**（原行数加 1），不能只用重复 idx 覆盖记录、合并同名／同索引条目或把第一行当作失败位置。有效基线已保证原行都通过 M.unknown，追加的未知派生形式才是指定失败。

如果副本字段数、换行、十六进制或数值宽度错误，导致解码失败，不能碰巧以同一 M.unknown 失败编号通过：有效命中条件 4（`:415`）单独拒绝副本构造、差异核对、解码或评估器错误；条件 3 还要求指定检查实际执行且失败／未评估集合恰好匹配。生产 R(L) 若不能解码，则保存原始错误、基线无效；不能把评估器错误当作计划的名字反例。

## 5. 非阻塞 N-137-1：索引句的适用对象

**位置：候选稿 §5.3 稳定表示的 idx 说明，`docs/wp2.5-c9-host-set-method-draft.md:380`；PR 描述的第四稿固定源码说明也有对应表述。**

**最小精化**：将该句写为“完整 Symbols 的零基位置 j 对应真实索引 j+1；筛选 STT_FUNC 时携带该真实索引，L 首项可以大于 1，索引可以有间隔”。PR 回执中“L 的 idx 从 1 开始”的推论同样应避免。
