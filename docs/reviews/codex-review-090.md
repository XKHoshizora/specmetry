## 3．B1：O3 后宿主禁用——可以关闭

### 3.1 规则及同步

本轮将两种状态分开：

- **宿主禁用状态**：一次执行以 O3 结束后置位，只进不出，持续到同一宿主进程结束。
- **资源清单**：接手未返回的复制任务、挂起的停止任务，持有它们并读取持续保存的结果；任务结束后可以移除。

[§8.6 H 维度:645](../wp2.5-check-runner.md#L645)、[规则 6:697](../wp2.5-check-runner.md#L697)、[E1～E4:762](../wp2.5-check-runner.md#L762) 已一致。E3 不再恢复宿主；E4 明确新进程是新宿主，不是原宿主恢复。§4.1 第2步、§7.5、F2、O3说明、§9.1复用、§11.4、D20/C-4、影响矩阵均同步到持续禁用。

[architecture:707](../architecture.md#L707) 与 [MVP-EV-29:197](../acceptance-criteria.md#L197) 明确：任务全部结束、资源释放、清单清空后，新的调用仍拒绝。没有以“正式入口是单次 CLI”豁免进程内准入契约。

### 3.2 原反例的静态复核

| 步骤 | 本轮规则的结果 |
|---|---|
| 第一次调用以 O3 结束 | 宿主禁用；当前批次停止；未结束任务有清单所有者 |
| 任务后来全部结束 | 读取结果，移除清单项，按实际情况释放资源 |
| 清单变空 | 禁用状态不变 |
| 同一宿主再次调用 | 在 DB、Git、进程启动之前拒绝，退出6 |
| 新进程调用 | 新宿主未禁用；仍须经过其他通常前置检查 |

Review 089 的“清空即重新执行”反例已被条文排除。这里证明的是规则修正，不是生产准入已实现。

### 3.3 保留的冻结前规格

原子置位/准入的锁、置位前已准入调用的处理、每项再次检查的位置、资源清单生存期、晚到错误报告和宿主退出说明，在规则6与G1中继续明确列为 F 类。每项开始前再检查仍是候选，没有被当成已验证的并发解决方案。本轮没有自行扩大 C-4 到所有残留资源；新增触发条件见 §6。

## 4．B2：J、停止任务与资源移交——可以关闭

### 4.1 时间线与所有者

[S6:538](../wp2.5-check-runner.md#L538) 的顺序现为：

1. 取得 J 起点，建立唯一截止；本次所有被停止流共用它。
2. 才启动各停止任务。可能阻塞的句柄准备、取消、关闭全部放在停止任务内，不在 J 前同步等待。
3. 复制结束与停止完成都受同一截止约束；不会逐流重新获得完整 T_join。
4. J 到期或两类任务都已结束后，封闭全部复制入口；不因停止仍挂起而等它无限返回。
5. 分开报告请求、停止完成、复制结果、封闭与资源状态；未完成任务移交，不丢弃。

停止完成不等于停止成功；O1/O2/O3只描述复制。带错完成的结果在当次说明中保留；挂起任务由调用方接手并进入宿主清单，其晚到结果继续由该任务保存、由清单所有者读取，后续成功不清除旧错误。晚到错误的具体呈现与宿主退出仍属 G1，没有假称已完成生产接线。

这里的“资源释放”是后续条件，不能由 J 返回、任务登记或入口封闭直接推出。完成但关闭失败的资源，也不得仅凭 done 字样声称已释放；错误、实际句柄归属与最终释放动作需要在 G1 的规格中继续写定。

### 4.2 原反例与边界

**停止一直不返回：** F1或D到期进入J → 先建截止 → 停止在工作任务中阻塞 → 主路径按阶段截止结束等待 → 封闭入口 → 报告pending并移交。原“Close挡在J之前，所以永远到不了封闭”的依赖已撤回。

**多个流：** 一路正常结束，另一路停止或复制仍pending，后一路使用同一截止并单独移交，前一路成功不代替后一路状态。

**晚到错误：** 返回时pending的停止后来带错结束，接手者读取的是持续保存结果的任务，而非移交时的过期快照。因此没有用“复制后来结束/清理成功”覆盖错误的规则。

**D内全部复制已经结束：** 正文明确此分支可以不进入J，因为没有仍在读取的复制任务，不需要等待那个读取引用。普通文件关闭不因此得到硬实时保证，关闭错误仍须保存；这不再是原先持有读取引用时先同步Close的反例。

S1终止未确认与F1均显式跳过D，采用相同的“先J截止、再停止、封闭、报告、移交”入口；正常路径的D/J仍独立。§8.3、S6、时限说明、EV-29、测试计划、C-2/C-3及G1/G2已同步。时间公式现在限制的是本程序的阶段等待，明确另有上下文、写入/输出和调度成本，不把挂起任务移交后的时间说成已经回收，也不宣称硬实时。

Windows重复取消继续是受控管道布局下的技术候选，没有扩大成任意Reader/驱动保证。没有用文档CI代替其实现证据。

**裁定：B2 可关闭，限于本轮协议顺序、共同截止、结果所有权和移交的条文修正。** G1/G2 的精确生产接口和必要验证仍未全部满足。

## 5．B3：D19 时间与知识状态——可以关闭

[§10.1:956](../wp2.5-check-runner.md#L956) 不再以“未观察到 E-main”证明主进程仍存活。定义分为：

| 路径 | duration_ms | exit_code与展示 |
|---|---|---|
| 可靠取得主进程退出信息 | 按正常路径定义的开始至观察退出区间 | 正常退出取其退出码；Unix信号等按既有规则为NULL |
| 未可靠取得，实际仍运行 | 开始至首次终止请求S3的定义区间 | NULL；不是实际运行时间或上下界 |
| 未可靠取得，实际早已退出 | 与上一行同一替代区间定义 | 同样NULL；不声称知道真实退出/运行时长 |
| 没有启动进程 | 0 | 不虚构退出事件；input_missing/spawn_error等按各自规则 |

D19的finished_at仍是放弃等待、尝试记录的展示时刻，不是实际结束时刻；D6在未启动时duration=0的含义也明确补齐。表、§8.3、F1、[data-model:379](../data-model.md#L379)、EV-28、E9、影响矩阵与G12保持一致。

原反例 t0启动、t1退出且观察失败、t2才请求终止：现在记录t2−t0，但明确只是这个区间，不再断言它是t1−t0的下界。实际仍运行的另一条历史同样只使用定义区间，不凭NULL或缺少E-main判断存活。原错误推论消除。

当次输出能够根据当前知识说明采用哪种定义；历史行不一定能区分D19两种分支、Unix信号或D6。本轮新增明确的展示限制：对于context_changed且tree_state_end=unknown的历史行，不将数值称为实际运行时间。没有增加新字段、改写历史行或改变seq推导规则。

**冻结前的一个精确化点：** G2仍需将“S3首次终止请求”落实为确定的本地事件/时间点。尤其身份复核失败、禁止实际发信号时，应明确使用进入/提出S3逻辑终止请求的时刻，不能要求为了取得时间而向身份未确认对象发信号，也不能假定一定发生了kill/Terminate API调用。当前条文把它标为S3且把精确位置留在G2，可按这个逻辑阶段解释；这是冻结前需写定的接口细节，不恢复原来的虚假运行时长界限，不单独阻塞本准备文档。

**裁定：B3 可关闭。** 该结论不表示时间字段能在没有新增元数据的情况下证明所有历史分支，也不表示未来实现已验证。

## 6．新增 G1 待决：复制结束、停止挂起

### 6.1 批准范围及 O1 组合

[规则6:707](../wp2.5-check-runner.md#L707)、[G1:1363](../wp2.5-check-runner.md#L1363)、[§107:6435](../review-resolution.md#L6435) 将“O2 + 停止挂起是否禁用”列为新增待确认，**没有自行启用**。这一区分正确：现有C-4的触发明确是复制未确认结束的O3，不是所有停止任务pending。

不过，“复制已返回”不只有O2。按当前定义，**O1 + 停止挂起也可能出现**：

1. D到期时复制尚未返回，因此建立J并启动停止任务。
2. J中复制自行读到本轮管道EOF、全部写完并返回。
3. 停止任务尚未完成关闭，例如仍在准备/关闭中，或者尚未获得继续执行的调度；J到期时其结果仍pending。
4. 复制按定义是O1，停止仍挂起；二者无逻辑蕴涵关系。

这是文档允许的事件序列，不是新的机制实验或实际平台复现。它不依赖故意不可信helper、PID复用或新的资源豁免。O1只证明输出完整，不证明停止任务/句柄资源已经结束。

| S6终态 | 现有C-4 | 当前/后续影响 |
|---|---|---|
| O3，停止已结束或仍挂起 | 已批准触发 | 同宿主持续禁用，当前批次停止6 |
| O2，停止挂起 | 尚未批准扩展 | 当前批次已有D20停止6；未来同宿主准入策略待定 |
| O1，停止挂起 | 同样超出现有触发 | 输出完整，不应假改为O2；是否中止当前批次/改退出码及后续禁用都必须明确 |
| O1/O2，停止已结束但带错 | 不能仅靠done推出成功释放 | 按已知错误与实际资源状态处理；不自动把它解释为现有O3触发 |

### 6.2 推荐的最小完整扩展——尚未批准

建议负责人考虑下列规则，而非只增加“O2”特例：

> 在S6终态报告/移交的线性化点，只要本次任一路复制任务或停止任务仍未确认结束，无论输出分类是O1、O2还是O3，均持续禁用当前宿主。当前调用不再开始后续检查项，CLI以environment/6中止；已准入并发调用的下一项按冻结的准入协议处理。任务结束、结果读取或资源清单清空不撤销禁用。入口仍先封闭，任务仍有明确所有者；新调用在DB、Git和进程访问之前拒绝。输出已完整的仍保留O1，当前执行的result和qualifying仍按其他状态及冻结公式决定，不因禁用本身变更；已有事实保留，不暗示安全重跑。

这比现有C-4多了触发条件；对“O1 + 停止挂起”还明确增加了当前批次中止/6的行为，**这些都需要负责人决定**。本报告只推荐这一完整组合，不以“资源保护”名义代批。若负责人只选择禁用未来调用，仍需另外写定同一已准入调用后续项的行为，不能遗漏这一层。

代价是一次已经完整转发、甚至合格pass的执行，也可能因为停止资源未确认而中止批次并使同宿主不能继续使用；单次CLI通常以继承路径执行，进程内测试/未来宿主的影响更直接。收益是不会在仍有未知异步资源时继续接纳新检查。**禁用不释放资源，也不取消已有证据效力。**
