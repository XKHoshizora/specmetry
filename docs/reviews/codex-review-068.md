### 2. 独立库层反例

在两个真实提交 A、B 的隔离仓库中：A 有 `d/a.go`，正文 `one\ntwo\n`，没有 `d/ghost.go`；B 增加 `d/ghost.go`。HEAD 固定回 A，显式接口也传 A。健康对照为 `d/a.go:1=true`、`d/ghost.go=false`、`d/a.go:999=false`。

每种场景使用新仓库，只改变实际用于该路径检查的一个对象；分别调用显式 HEAD 和自行解析 HEAD 的接口。结果在 Windows Git 2.56.0.windows.2 与 WSL Git 2.43.0 一致：

| 对象变化 | 目标版本实际结果 | 正确结果／裁定 |
|---|---|---|
| blob 的 zlib 载荷为 `blob 500\0one\n`，头部可读但正文截断 | 两接口均成功，`d/a.go:1` 被标 true | 必须环境错误，无部分标记；**反例成立** |
| 原 blob ID 的文件中放入另一个合法 blob 的完整字节 `blob 6\0other\n` | 两接口均成功，按替代正文计数 | 必须环境错误；**反例成立** |
| A 的 `d` 子树对象文件中放入 B 的 `d` 子树完整字节，ID 路径仍是 A 的子树 ID | 两接口均成功，把 A 原本没有的 `d/ghost.go` 标为 true | 必须环境错误；**固定快照的假存在已直接证明** |
| A 根树对象替换为 B 根树对象 | 本夹具两接口均环境错误 | 拒绝对照通过；不据此宣称所有根树损坏均已覆盖 |

每次检查前后比较 `.git` 内容及 mtime，没有由读取引起的修改；恢复原对象字节后，三个健康路径／行号对照重新成立。损坏注入是在隔离对象库中完成，不涉及真实远端或用户仓库。
