## 5. 已成立的修订与精化

### 5.1 B-140-1 的原问题

可以关闭原来的“一律把省略当成缺失”问题：

- 第一种调用的所选八个键是字符串映射；空 GOFLAGS 是已取得的空字符串，不是没有该键。
- Context 的 false／空字段按零值理解，健康 CgoEnabled=false 不需要键出现。此裁定只针对字段规则，不把 B-141-1 的命令当成可执行。
- 第三种调用是多个 PackagePublic JSON 对象的流，不是一个数组；只清零未请求的**顶层**字段，Module 的全部已定义子字段仍须按固定 JSON 形式处理。
- 标准库 Module=nil，主模块 Main=true 且没有依赖版本／Sum，第三方模块 Standard=false／Main=false 的正常省略，都有分支。
- Time 等“不消费字段”仍须按其实际 JSON 表示解码，不能把 Go 的结构体类型机械当作 JSON 对象。例如 Module.Time 经时间类型的 JSON 方法表示为字符串；固定 JSON 定义是依据，不是“看到未知类型便忽略”的许可。
- 重复键、大小写变体、未知键、类型错误和明确 null 有拒绝规则；正常省略与非零调用后的未知分开，后者不虚构空值。
- `unsafe` 在正常固定安装中是标准库包记录；固定装载链会经 go/build 取得其包元数据。其特殊性是 **导入返回 types.Unsafe、不以文档占位源码建类型**，不是据此推断正常记录必然缺少 Dir。本轮没有把这一提示臆造成新的 healthy-rejection 缺陷。仍须沿用实施计划第 1355 行的特殊装载规则，不能因第 316 行的通用说明又去解析 unsafe 的占位声明。

Module.Sum／GoModSum 的填充有缓存与源码条件，第二稿已把“实测会取得”留给将来。没有取得必要值即拒绝是允许的证据不足出口，不把 go.sum 中存在一行当作 cmd/go 已返回它。

### 5.2 B-140-2：H/C/P 与 I-6(d)

本轮可采的关联链为：H 枚举名字并读取全部模块普通文件 → 计算模块 h1、记录 M → C 的全部条件候选与 P 的全部 GoFiles 经受控接口取得 B → 实际判断、预筛、解析、约束行与列号基于这些 B。

- C 明确包括未编入分析 GoFiles、却影响条件差异的文件；x/sys 的生产变体导入核对也列入。没有通过删检查来闭合覆盖。
- OpenFile 不回退，真实文件读取／关闭在受控层完成；交给 MatchFile 的内存 ReadCloser 不代表外部句柄已被它正确关闭。
- 固定 `go/build.Context.ReadDir` 需要按 Name 排序的 FileInfo，而不是裸字符串。H 的普通文件名字、字节数与已确认的普通文件类型可支撑当前逐包候选用途；当前源码消费 Name／IsDir／Type，目录在候选循环中被跳过。不能为了构造 FileInfo 再查询实时目录，恢复未经绑定的选择输入。
- **非阻塞定稿精化 N-141-1：**第 201 行最好明确 ReadDir 是本用途的受控视图，规定名字排序、普通文件元数据的来源，以及目录记录是否保留／不进入候选；Size 可以取记录字节数，未使用元数据不得伪称现场值。当前 MatchFile＋规定候选范围可以实现，不因此要求新文件系统机制，也不将其泛化为完整 go/build.Import 的文件系统替身。

**I-6(d) 独立核对结果：**规定的第三种调用没有 `-compiled`。PackagePublic.Imports 起于 build.Package 的源码导入，RawImports 保留原导入；解析导入时只在原公开 Imports 的长度内替换为规范路径。内部增补的链接／编译依赖在另一个 importPaths／CompiledImports 路径中，不能一概算成公开 Imports。只有 `-compiled` 等相应路径才把 CompiledImports 合入公开表。ImportMap 将原路径映射到规范路径。

所以，在本稿限定的 P、非 cgo 分支及固定调用下，源码 import 集合经本包 ImportMap 后与公开 Imports 作集合比较，有充分的静态基础。特殊 unsafe 的导入字符串也可以参与集合比较，不因此改为解析 unsafe 的文档占位类型。不能把这一结论推广到 `-compiled`、测试变体或任意未来调用。
